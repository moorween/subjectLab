# subjectLab

Стенд для проверки `lib/subject.cpp` на реальном ESP32 (nodemcu-32s / любая ESP32-плата).

## Запуск

1. Открыть папку в VS Code с PlatformIO.
2. Ничего не подключать. **GPIO27 и GPIO33 должны быть свободны**: тест `fromPin`
   переключает их внутренние подтяжки.
3. Upload and Monitor (115200).
4. Тесты стартуют через 1,5 с после сброса. В конце — `ИТОГ: ВСЁ OK` или список
   проваленных проверок с номерами строк.

Команды в мониторе порта:

- `r` — прогнать тесты ещё раз (без перезагрузки);
- `l` — серия из 20 прогонов подряд: печатаются только ошибки, в конце — какие тесты и
  сколько раз падали. Нужна, чтобы ловить редкие сбои.

В тесте «Исключения» печатаются две ожидаемые ошибки — так и должно быть (в серии тоже).

Если проверка «дождаться события» не прошла, печатается диагностика: состояние задач
всех циклов, длина очередей, сколько задач выполнено и потеряно, время ответа на пробную
задачу, и пришло ли событие с опозданием.

После каждого теста выполняется барьер: тест ждёт, пока все циклы доделают задачи из
очереди, чтобы задачи одного теста не попали в следующий.

## Что проверяется

| № | Тест |
|---|---|
| 1–4 | `next`, отсев повторов, `update`, `forceUpdate`, обе формы `subscribe`, `Subscription::complete`, `Subject::complete` (в т.ч. из колбэка) |
| 5–8 | `pipe` (цепочки, ветвление, вложенность), `rejectNext`, `matchTo`, `filter`, `avg`, `median`, `SubFilters::forceUpdate` |
| 9–11 | `BehaviorSubject`, исключения в подписчиках и фильтрах, типы `String` и структура |
| 12 | `fromPin` через `Async`: `digitalRead` (GPIO27), `analogRead` (GPIO33) |
| 13 | `CoreLoop`: выполнение на нужном ядре, порядок FIFO, переполнение очереди |
| 14 | Домашний цикл, `Delivery::Queue`: 50 значений с другого ядра, `update()` |
| 15 | Домашний цикл у глобального Subject (`on()`) и у Subject в `shared_ptr` |
| 16 | `Delivery::Latest`: 100 значений при занятом цикле → одна задача |
| 17–18 | `subscribe(cb, loop)`, `observeOn(loop)`, `BehaviorSubject` с циклом |
| 19 | `fromPin` с опросом на ядре 0; при повторном прогоне — удаление объекта с работающим таймером |
| 20 | `Action`: вызов с ядра 0 на ядре 1, несколько параметров, отписка, `Action<>` |
| 21 | Нагрузка: 2000 значений на ядре 0 при одновременных подписках/отписках; два отправителя разного приоритета в один Subject |
| 22 | Память: нет утечек на 3000 межъядерных сообщениях |

## Файлы

- `lib/subject.cpp` — библиотека, описание API в `lib/subject.md`
- `lib/coreloop.h` — очередь задач ядра (`CoreLoop`, `Delivery`)
- `lib/async.cpp`, `lib/async.h` — таймеры (из gateKeeper; добавлен include guard)
- `src/main.cpp` — тесты
