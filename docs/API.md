# subjectLab — API

Небольшая библиотека в духе RxJS. Источник (`Subject`) рассылает подписчикам новые
значения, их можно пропускать через фильтры (`pipe`), привязать к пину, а с помощью
`CoreLoop` — передавать между ядрами (задачами FreeRTOS).

```cpp
#include <Subject.h>   // подключает также CoreLoop.h и Async.h
```

Подключение к проекту — см. [README](../README.md).

Требования: C++17 (на pioarduino ESP32 по умолчанию gnu++2b), включённые исключения
(на ESP32 включены по умолчанию). Для типа значения `T` нужны конструктор по умолчанию,
копирование и `operator==`.

---

## Быстрый пример: датчик на ядре 0, защита на ядре 1

```cpp
CoreLoop core0Loop, core1Loop;
std::shared_ptr<Subject<float>> current;      // храним всё время работы
Action<String> breakAll(core1Loop);           // «вызов функции» на ядре 1

void core0Task(void*) { for (;;) { loopMqtt(); core0Loop.run(pdMS_TO_TICKS(5)); } }
void core1Task(void*) { for (;;) { loopGate(); core1Loop.run(0); taskYIELD(); } }

void setup() {
  xTaskCreatePinnedToCore(core0Task, "core0", 8192, nullptr, 1, nullptr, 0);
  xTaskCreatePinnedToCore(core1Task, "core1", 8192, nullptr, 3, nullptr, 1);

  breakAll.subscribe([](String reason) { gate.breakAll(reason); });   // выполнится на ядре 1

  current = Subject<float>::create(core0Loop, 100);   // опрос АЦП на ядре 0 раз в 100 мс
  current->fromPin(35)
         ->pipe({ SubFilters<float>::median(30) })
         ->subscribe([](float v) {
           mqttSetValue(mqttCurrent, v);                     // ядро 0
           if (v > 30) breakAll.call("Main Line Overcurrent");  // уходит на ядро 1
         });

  // Показания для экрана на ядре 1 — только последнее значение, без очереди
  current->subscribe([](float v) { screen.show(v); }, core1Loop, Delivery::Latest);
}
```

## Как распространяется значение

`next(value)`:

1. Если у Subject есть **домашний цикл** и вызов идёт из другой задачи — значение
   ставится в очередь этого цикла, и дальше всё происходит там.
2. Если значение равно предыдущему входному (`rawValue`) и нет принудительного
   обновления — ничего не происходит. **Первое значение проходит всегда**, даже если
   оно равно `T()`.
3. Значение проходит фильтры `pipe`. Фильтр может отбросить его: `subject->rejectNext()`.
4. Результат (`value`) уходит в дочерние Subject (`pipe`, `observeOn`).
5. Если входное значение отличается от последнего разосланного — вызываются подписчики.
   Подписка со своим циклом получает значение в задаче этого цикла.

Колбэки вызываются без удержания внутреннего замка, поэтому из них можно
подписываться, отписываться и вызывать `complete()`.
Исключения в фильтрах и подписчиках перехватываются и печатаются в `Serial`:
ошибка фильтра прерывает обработку значения, ошибка подписчика не мешает остальным.

## CoreLoop — очередь задач ядра

| Член | Описание |
|---|---|
| `CoreLoop(size_t queueLen = 32, TickType_t postTimeout = 10 мс)` | Очередь на `queueLen` задач. |
| `run(TickType_t maxWait = 0)` | Крутить в бесконечном цикле своей задачи: ждёт задачу до `maxWait`, выполняет накопившиеся, затем `async.tick()`. Задача, вызывающая `run()`, становится владельцем цикла. |
| `post(fn)` / `post(fn, wait)` | Выполнить `fn` в задаче цикла. Можно из любой задачи (не из прерывания). `false` — очередь полна, задача потеряна. Из своей же задачи не ждёт. |
| `isCurrent()` | Вызвано ли из задачи-владельца. |
| `task()`, `core()` | Задача-владелец и её ядро (после первого `run()`). |
| `dropped()`, `pending()` | Сколько задач потеряно; сколько ждёт в очереди. |
| `executed()`, `lastRun()` | Сколько задач выполнено; `millis()` последнего входа в `run()` (для диагностики зависаний). |
| `setPostTimeout(t)` / `postTimeout()` | Сколько `post()` без явного `wait` ждёт места в очереди (по умолчанию 10 мс). |
| `async` | Таймеры этого цикла. `Async` не потокобезопасен — трогайте его только из задачи цикла или через `post()`. |

`run(pdMS_TO_TICKS(5))` удобно ставить вместо `vTaskDelay(5)`: задача так же спит,
но просыпается сразу, как только придёт задача.

`enum class Delivery`:

- `Delivery::Queue` — каждое значение отдельной задачей (события, команды).
- `Delivery::Latest` — пока задача ждёт в очереди, новые значения её перезаписывают;
  в очереди не больше одной задачи от источника. Для датчиков.

## Subject&lt;T&gt;

### Создание

| | |
|---|---|
| `Subject<T> s;` | Обычный объект (глобальный, поле класса). Синхронный. |
| `Subject<T>::create()` | То же в `shared_ptr`. |
| `Subject<T>::create(CoreLoop& loop, int delay = 100, Delivery = Queue)` | С домашним циклом `loop`; `delay` — период опроса для `fromPin`. |
| `Subject<T>::create(Async* async, int delay = 100)` | Старый вариант: опрос через `Async`, без домашнего цикла. |
| `s.on(CoreLoop& loop, Delivery = Queue)` | Назначить домашний цикл существующему Subject (до использования из других задач). |

Объекты из `create()` с таймером (`fromPin`) **храните** всё время работы: таймер
держит указатель на объект.

### Методы

| Член | Описание |
|---|---|
| `next(v)` / `next(v, true)` | Отправить значение / принудительно, даже если не изменилось. Из любой задачи. |
| `update()` | Повторно разослать последнее значение. |
| `forceUpdate()` | Постоянный режим: каждое `next()` рассылается. |
| `subscribe(void(T))` | Подписка; колбэк в задаче, которая рассылает (домашний цикл или вызывающая). |
| `subscribe(void(T, Subscription<T>*))` | Колбэк может отписаться сам: `sub->complete()`. |
| `subscribe(cb, CoreLoop& loop, Delivery = Queue)` | Колбэк всегда выполняется в задаче `loop`. Обе формы колбэка. |
| `pipe({ f1, f2, ... })` | Дочерний Subject с цепочкой фильтров. Работает в той же задаче, что и родитель. |
| `observeOn(CoreLoop& loop, Delivery = Queue)` | Дочерний Subject, который обрабатывает и рассылает значения в задаче `loop`. Дальше можно `->pipe(...)->subscribe(...)`. |
| `fromPin(pin, mode)` / `fromPin(pin)` | Опрашивать пин: `digitalRead` для `bool`, `analogRead` для остальных. Без `mode` — `INPUT_PULLDOWN`. |
| `rejectNext()` | Отбросить текущее значение (из фильтра). |
| `complete()` / `completed()` | Завершить: отписать всех и больше ничего не рассылать. |
| `get()` | Текущее значение — **безопасно из любой задачи**. |
| `value`, `rawValue` | Текущее (после фильтров) и последнее входное значение. Из чужих задач читайте `get()`. |

Фильтр — функция `T(T value, std::shared_ptr<Subject<T>> subject)`:
`[](float v, auto) { return v * 2; }`.

### Subscription&lt;T&gt;

`complete()` — отписаться (из любой задачи), `completed()` — проверить.
Возвращаемый `shared_ptr` хранить не обязательно.

### BehaviorSubject&lt;T&gt;

Subject с начальным значением: новый подписчик сразу получает текущее значение
(подписка со своим циклом — в задаче этого цикла).

```cpp
BehaviorSubject<int> mode(0);
mode.subscribe([](int m) { Serial.println(m); });   // сразу печатает 0
BehaviorSubject<int> speed(50, core1Loop);           // с домашним циклом
```

### SubFilters&lt;T&gt;

| Фильтр | Описание |
|---|---|
| `median(frame)` | Медиана по `frame` последним значениям. |
| `avg(frame)` | Скользящее среднее. |
| `matchTo(v)` | Только значения, равные `v`. |
| `filter(pred)` | Только значения, для которых `pred(v) == true`. |
| `forceUpdate()` | Переводит Subject в режим `forceUpdate`. |

У фильтра своё состояние — создавайте отдельный экземпляр на каждый `pipe()`.

## Action&lt;Args...&gt; — вызов функции на другом ядре

Для команд: значения не сравниваются, каждый вызов доставляется; параметров может
быть несколько, без структур.

```cpp
Action<int, bool> moveGate(core1Loop);       // объявление (глобально)

moveGate.subscribe([](int speed, bool open) {  // ядро 1
  gate.move(speed, open);
});

moveGate.call(80, true);                     // с любого ядра, не блокирует
moveGate.callWait(pdMS_TO_TICKS(50), 80, true);  // ждать место в очереди до 50 мс
```

| Член | Описание |
|---|---|
| `Action<Args...>(CoreLoop& home)` | Обработчики выполняются в задаче `home`. Без цикла — синхронно. |
| `subscribe(void(Args...))` | Обработчик; возвращает `Subscription` (`complete()` — отписать). |
| `call(args...)` | Вызов; `false` — очередь домашнего цикла полна. |
| `callWait(wait, args...)` | То же с ожиданием места в очереди. |

Объект `Action` должен жить, пока есть необработанные вызовы (объявляйте глобально).

## Remote&lt;R(Args...)&gt; — вызов функции на другом ядре с ответом

Функция с результатом, которая всегда выполняется в домашнем цикле. Вызвать можно
с любого ядра: асинхронно (ответ придёт в колбэк) или с ожиданием результата.

```cpp
Remote<float(int)> readAdc(core1Loop);           // объявление (глобально)

readAdc.handle([](int pin) {                     // обработчик — на ядре 1
  return analogRead(pin) * 3.3f / 4095;
});

// Асинхронно: ответ выполнится в задаче core0Loop
readAdc.call(34, [](float v) { mqttSetValue(mqttVoltage, v); }, core0Loop);

// Асинхронно: ответ выполнится на ядре 1, сразу после обработчика
readAdc.call(34, [](float v) { /* ... */ });

// С ожиданием до 100 мс (std::optional: пусто — не дождались или ошибка)
if (auto v = readAdc.callSync(pdMS_TO_TICKS(100), 34)) Serial.println(*v);
```

| Член | Описание |
|---|---|
| `Remote<R(Args...)>(CoreLoop& home)` | Обработчик выполняется в задаче `home`. Без цикла — синхронно. |
| `handle(R(Args...))` | Задать обработчик (один; новый заменяет старый). |
| `call(args..., reply, CoreLoop& replyLoop)` | Вызов; `reply(R)` выполнится в задаче `replyLoop`. `false` — очередь домашнего цикла полна. |
| `call(args..., reply)` | То же, `reply` выполнится в домашнем цикле. |
| `callSync(timeout, args...)` | Ждать результат до `timeout` тиков; возвращает `std::optional<R>`. Из домашнего цикла выполняется сразу, без очереди. |

Если обработчика нет или он бросил исключение, ответа не будет (`callSync` вернёт
пустое значение, исключение печатается в `Serial`). Если `callSync` не дождался,
вызов всё равно выполнится позже, а результат будет отброшен.

Осторожно с взаимным ожиданием: если обработчик в цикле B вызывает `callSync` к
циклу A, а A в это время сам ждёт B через `callSync`, оба простоят до таймаута.
Для `void`-функций без ответа используйте `Action`.

## Async — таймеры

`Async` выполняет задачи по времени; `tick()` нужно вызывать в цикле. У каждого
`CoreLoop` есть свой `async` (его `tick()` вызывает `run()`).

```cpp
Async timers;

Job led = timers.repeat(500, []() { digitalWrite(2, !digitalRead(2)); });   // каждые 500 мс
timers.delay(3000, []() { Serial.println("прошло 3 с"); });                 // один раз
timers.repeat(100, [](CallbackParams p) {                                    // сразу и каждые 100 мс
  if (p.loopCount == 10) p.breakFn();                                         // 10 раз и стоп
});

void loop() { timers.tick(); }

led.pause(); led.resume(); led.breakFn();   // управлять задачей снаружи
```

| Член | Описание |
|---|---|
| `delay(ms, fn)` | Один раз через `ms`. |
| `repeat(ms, fn)` | Каждые `ms`, первый раз через `ms`. |
| `repeat(ms, fn(CallbackParams))` | Каждые `ms`, первый раз на ближайшем `tick()`. В `CallbackParams`: `loopCount` (с 1), `iterationTime`, `breakFn()`. |
| `queue(fn)` | Один раз на ближайшем `tick()`. |
| `clearAll()` | Отменить всё. |
| `size()` | Сколько задач активно. |
| `Job::breakFn()` | Отменить задачу. |
| `Job::pause()` / `resume()` | Приостановить / продолжить. |
| `Job::untilFn(fn)` / `whileFn(fn)` | Остановить, когда `fn(params)` вернёт `true` / как только вернёт `false`. |
| `Job::run()` | Выполнить колбэк сейчас (у задачи из `delay()` — выполнить и отменить). |

Внутри колбэка можно отменять свои и чужие задачи, вызывать `clearAll()` и добавлять
новые задачи (они выполнятся не раньше следующего `tick()`). `Job`, переживший свой
`Async`, безопасен: его методы ничего не делают. `Async` не потокобезопасен — все вызовы
из одной задачи; для `CoreLoop::async` — из задачи цикла или через `post()`. Объект
нельзя копировать.

## Правила для нескольких ядер

- Каждый Subject обрабатывает значения в одной задаче: в домашнем цикле, если он
  задан, иначе в той, что вызывает `next()`. Без домашнего цикла не вызывайте `next()`
  одного Subject из разных задач одновременно.
- `next()`, `subscribe()`, `complete()`, `get()`, `Subscription::complete()` и
  `Action::call()` безопасны из любой задачи.
- Колбэк, который уходит в другой цикл, не должен ссылаться на локальные переменные
  функции, которая уже завершилась. В задачу копируется значение.
- Из прерываний вызывать нельзя.
- Каждое межъядерное сообщение — одно выделение памяти; при переполнении очереди оно
  теряется (`CoreLoop::dropped()`).
- **Приоритеты отправителей.** Когда в полной очереди освобождается место, FreeRTOS
  отдаёт его ждущей задаче с самым высоким приоритетом. Если в одну очередь непрерывно
  пишут две задачи, задача с низким приоритетом может не дождаться места за 10 мс и
  потерять сообщение. Для важных команд используйте `callWait()` / `post(fn, wait)` с
  большим ожиданием или `setPostTimeout(portMAX_DELAY)`, а очередь делайте с запасом.
- **Время жизни.** Отложенные задачи и таймеры держат Subject из `shared_ptr` через
  `weak_ptr`: если объект удалён, они ничего не делают (таймер остаётся в `Async` пустым).
  Глобальные объекты и поля класса вызываются напрямую — они должны жить всё время работы.
  Вызовы `Action`, которые ещё стоят в очереди после удаления объекта, ничего не делают.
- Глобальный Subject помнит последнее значение: повторная отправка того же значения
  (например, при перезапуске логики без перезагрузки) отсеивается — используйте
  `next(v, true)`, если нужно разослать его ещё раз.

## Отличия от версии в gateKeeper

| Было | Стало |
|---|---|
| Первое `next(T())` (например, `next(false)` у `Subject<bool>`) отсекалось | Первое значение проходит всегда |
| `BehaviorSubject(5)` затем `next(0)` отсекалось | Доставляется |
| `complete()` из колбэка портил итерацию | Безопасно |
| — | `CoreLoop`, `Delivery`, `on()`, `create(CoreLoop&)`, `observeOn()`, `subscribe(cb, loop)`, `get()`, `Action`, `Remote`, `SubFilters::filter()` |
| `Async`: `breakFn` из колбэка, `clearAll()` из колбэка и задачи с одинаковой задержкой портили память | Исправлено; добавлены `queue()`, `size()`, `Job::resume`; `Async` нельзя копировать |
| `Job` по умолчанию: `run()` бросал исключение | Ничего не делает |
| `create(Async*)` сразу заводил таймер | `create(CoreLoop&)` заводит таймер только в `fromPin()` |
